# Oliver-200 · FX «ROSE LASER / DEEP SPACE»

Офлайн-рендер: персонаж **строится геометрией с нуля** и рендерится
собственным софтверным растеризатором, ставится в процедурный космос и
получает **розовые лазеры из глаз** плюс набор «ультра»-эффектов.
Ни нейросетей, ни интернета — только математика на numpy/OpenCV.

Фотография при этом не копируется, а **измеряется**: с неё снимается
палитра персонажа (мех, футболка, кепка, морда, кроссовки, цепь, миска),
и эти цвета идут в материалы 3D-модели. Получается тот же персонаж, но
собранный и освещённый заново, а не вырезанный.

## Два файла кода — один результат

| Файл | Подпись | Что внутри |
|---|---|---|
| `oliver_laser_space_plain.py` | `OLIVER200-FX-PLAIN` | **без шифровки** — открытый читаемый исходник, эталон логики |
| `oliver_laser_space_secure.py` | `OLIVER200-FX-SECURE` | **с шифровкой** — тот же код в аутентифицированном контейнере |

Оба дают **побайтово одинаковый PNG** при одном и том же `--seed`
(проверяется `sha256sum`).

## Запуск

```bash
# с фотографией: персонаж вырезается с неё, сверху крупная подпись
python3 tools/fx/oliver_laser_space_plain.py \
    --src photo.jpg --caption "Я ФИКСИРУЮ" --out out/oliver_laser_space.png

# без --src: персонаж строится геометрией с нуля
python3 tools/fx/oliver_laser_space_plain.py --out out/generated.png

# сгенерированная модель, но в цветах с вашего фото
python3 tools/fx/oliver_laser_space_plain.py \
    --mode generate --src photo.jpg --out out/generated_your_colors.png

# то же самое из зашифрованного файла
python3 tools/fx/oliver_laser_space_secure.py \
    --src photo.jpg --caption "Я ФИКСИРУЮ" --out out/oliver_laser_space.png

# проверить контейнер, ничего не рендеря
python3 tools/fx/oliver_laser_space_secure.py --verify
```

Ключи: `--mode auto|generate|photo` (по умолчанию `auto`: `photo`, если
задан `--src`, иначе `generate`),
`--width` / `--height` (по умолчанию 1400×2000; 256…6000, не больше
30 Мпикс), `--seed` (другой seed — другая туманность, звёзды, молнии и искры),
`--chins N` (сколько двойных подбородков нарастить, по умолчанию `0` —
выключено), `--cap-text OLIVER` (надпись на кепке блочным шрифтом),
`--caption "Я ФИКСИРУЮ"` (крупная фонк-подпись сверху),
`--cutout cut.png` (сохранить вырезанного персонажа отдельным PNG с альфой).

Зависимости: `numpy`, `opencv-python-headless`, `Pillow` (только для подписи).
Шифрованный файл дополнительных пакетов **не** требует — вся крипта на
стандартной библиотеке.

## Как это сделано

### Персонаж (режим `generate`)

1. **Геометрия.** Фигура собирается из ~52 коробок: ноги, кроссовки с
   подошвой, корпус, рукава, руки (поворот вокруг плеча), шея, голова,
   морда, нос, уши, щели глаз, кепка с козырьком, цепь из 18 звеньев,
   подвеска, миска с чесноком, указательный палец и каскад подбородков.
   Все размеры выведены из четырёх пропорций (длина ноги, высота корпуса,
   высота плеча, длина руки), поэтому правка одной не рассыпает фигуру.
2. **Растеризатор.** Свой, на numpy: перспективная проекция, z-буфер,
   отсечение задних граней по нормали, перспективно-корректная
   интерполяция, SSAA ×2. Два прохода — сперва глубина и индекс грани,
   потом затенение только видимых пикселей (нулевой overdraw).
3. **Свет и тени.** Ключевой розовый + холодный бирюзовый подсвет с мягкой
   «обёрткой» (`(N·L + k)/(1 + k)`), френелевский контровой, блик по
   Блинну-Фонгу. Тени — ортографическая карта глубины со стороны ключевого
   света, 1200×1200.
4. **Материалы.** Процедурные, в локальных координатах детали: мраморный
   мех (3D fbm на целочисленном хеше), ткань футболки, кепка, шерсть морды,
   золото цепи, бирюза кроссовок. Базовые тона берутся из палитры: если дан
   `--src`, пиксели силуэта раскладываются по цветовым семьям (по тону,
   насыщенности, яркости и положению по вертикали), и из каждой берутся
   устойчивые перцентили. Ни один пиксель фото в кадр не попадает — только
   измеренные с него цвета.
5. **Мелочи с оригинала.** Надпись на кепке набирается коробками блочным
   шрифтом 3×5, брови — отдельными планками над щелями глаз, в поднятой
   руке миска с чесноком, в опущенной — указательный палец.
6. **Подбородки.** `--chins N` валиков под челюстью: каждый следующий шире
   и сильнее нависает вперёд. Камера смотрит сверху, поэтому верхняя грань
   каждого валика ловит ключевой свет и между складками появляется
   читаемая линия.

### Сцена

7. **Космос.** Туманности (fbm с доменным искажением), звёздное поле со
   степенным распределением яркости и дифракционными лучами, газовый
   гигант с кольцами, луна, портальное кольцо, варп-полосы, пояс камней.
8. **Лазеры.** Два параллельных луча из щелей глаз (их экранные координаты
   берутся прямо из проекции 3D-модели): белое ядро, розовое тело,
   пурпурный ореол, бегущие кольца энергии, компактный блик. По дороге
   лучи режут мелкие астероиды — у тех светится раскалённая кромка.
9. **Поверх.** Плазменное пламя с силуэта, электрические разряды вдоль
   контура, парящие искры, наружное свечение.
10. **Пост.** Многомасштабный bloom, хроматическая аберрация, глитч-срезы,
   экспозиция, тон-маппинг, насыщенность, мягкая виньетка, зерно.

### Режим `photo`

Старый путь целиком сохранён: сегментация персонажа с зигзагового фона
(цвет + локальная плоскость в окнах 3/9/21 px, посевная реконструкция
компонент), растушёвка срезов кадра и искры дезинтеграции по кромке.

## Безопасность

Рендер (оба файла):

* `_safe_path()` — симлинк проверяется **до** `resolve()` (после разрешения
  проверять нечего), каталог/устройство вместо файла отсекаются, для вывода
  проверяется существующий каталог и что путь не занят не-файлом;
* защита от «бомбы сжатия»: лимит на размер файла (64 МБ) и на число
  пикселей входа (40 Мпикс) и холста (30 Мпикс);
* формат распознаётся по содержимому (`cv2.imdecode` из буфера), а не по
  расширению; файл не отдаётся библиотеке напрямую;
* все числовые параметры CLI зажаты в диапазон;
* запись атомарная: временный файл с правами `0600` → `chmod 0644` →
  `os.replace`, так что наполовину записанный кадр никому не виден и
  подменить цель через симлинк нельзя;
* ни `eval`, ни `pickle`, ни `os.system`, ни одного сетевого вызова.

Контейнер (`oliver_laser_space_secure.py`):

```
KDF        scrypt(N=2^15, r=8, p=1, dklen=64) → 32 байта ключ шифра + 32 ключ MAC
Шифр       поточный CTR на HMAC-SHA256: блок_i = HMAC(enc_key, nonce‖i)
Аутентиф.  Encrypt-then-MAC, HMAC-SHA256(mac_key, magic‖salt‖nonce‖len‖ct)
Контроль   SHA-256 расшифрованного текста сверяется с зашитым эталоном
```

MAC проверяется **до** расшифровки и сравнивается `hmac.compare_digest`,
поэтому подложить свой код в контейнер нельзя: любая правка байта — отказ
запуска, а не тихое исполнение подменённого кода. Только после MAC и сверки
SHA-256 payload компилируется и исполняется в отдельном пространстве имён.

**Про ключ — честно.** По умолчанию парольная фраза зашита в файл. Это
защита целостности и от случайного чтения, но **не секрет**: кто читает
файл, тот знает фразу. Настоящая защита — своя фраза и перешифровка:

```bash
export OLIVER_FX_KEY='ваша-длинная-парольная-фраза'
python3 tools/fx/oliver_laser_space_secure.py --rebuild tools/fx/oliver_laser_space_plain.py
python3 tools/fx/oliver_laser_space_secure.py --verify     # с той же фразой
```

Без правильной фразы `--verify` и запуск падают на проверке MAC.
