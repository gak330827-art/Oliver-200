# Oliver-200 — лаунчер Minecraft для Android

Лаунчер в виде APK: **выбор версии**, **скин по нику**, **паки шейдеров**.
Написан на Kotlin, вся логика вынесена в отдельный модуль без зависимости
от Android и покрыта тестами.

---

## Что делает

| Экран | Что умеет |
|---|---|
| **Версии** | Полный список версий с официального манифеста Mojang: релизы, снапшоты, старые альфы и беты. Фильтр по каналу, поиск, установка с проверкой SHA-1 каждого файла, распаковка нативных библиотек. |
| **Скин** | Поиск игрока по нику → UUID → профиль → текстура. Предпросмотр фигуры целиком, вид спереди, с шляпой и вторым слоем. Различает модели classic и slim. |
| **Шейдеры** | Импорт `.zip` через системный выбор файлов, распознавание типа пака (Iris/OptiFine, Canvas, core-шейдеры, Bedrock RTX), включение через `optionsshaders.txt` — тот самый файл, который читает Iris при старте. |
| **Аккаунт** | Официальный вход Microsoft → Xbox Live → XSTS → Minecraft. Токены в зашифрованном хранилище. Сборка полной команды запуска и передача её среде выполнения Java. |
| **Офлайн-ник** | Профиль без сети: вводите ник — получаете игрока с тем же UUID, который вычислит сам сервер. Для одиночной игры, локальной сети и серверов с `online-mode=false`. |

## Чего НЕ делает — и почему

**Не содержит саму игру и не обходит лицензию.** Скачиваются только
официальные файлы Mojang, а вход выполняется только через Microsoft
с проверкой лицензии (`entitlements`).

Офлайн-ник есть — это штатный режим самой игры (`--accessToken 0`,
`--userType legacy`), нужный для одиночного мира, локальной сети,
сервера с `online-mode=false` и на случай, когда серверы Mojang лежат.
Но **запуск** в офлайне открывается после первого успешного входа через
Microsoft: так лаунчер один раз убеждается, что игра куплена. Тот же
порядок принят в Prism Launcher и других открытых лаунчерах — офлайн
для владельца, у которого пропала сеть, а не способ играть без покупки.
Просмотр скинов, установка версий и управление паками работают всегда.

**Не включает в себя JVM.** Minecraft Java Edition требует настоящую
виртуальную машину Java и OpenGL — в Android нет ни того, ни другого.
Собственная сборка OpenJDK плюс трансляция GL в GLES — это отдельный
проект на сотни мегабайт нативного кода. Поэтому Oliver-200 честно делает
свою часть работы (аккаунт, версии, целостность, скины, шейдеры,
полностью собранная команда запуска) и передаёт готовую команду внешней
среде выполнения через интент `com.oliver200.launcher.action.LAUNCH_MINECRAFT`
(см. `app/.../mc/RuntimeBridge.kt` — контракт описан там полностью).

Локальный профиль без входа работает: смотреть скины и управлять паками
можно и без аккаунта, запускать игру — нет.

## Сборка

Нужны JDK 17 и Android SDK (compileSdk 34).

```bash
git clone <репозиторий> && cd Oliver-200

# Тесты логики — Android SDK не требуется вообще
./gradlew -Poliver.includeApp=false :core:test

# APK
./gradlew :app:assembleDebug          # app/build/outputs/apk/debug/
./gradlew :app:assembleRelease        # app/build/outputs/apk/release/
```

Модуль `:app` подключается автоматически, только если найден Android SDK
(`ANDROID_HOME`, `ANDROID_SDK_ROOT` или `sdk.dir` в `local.properties`).
Благодаря этому ядро собирается и тестируется где угодно — на сервере CI
без SDK в том числе.

Готовые APK собирает GitHub Actions на каждый push: вкладка **Actions** →
последний запуск → артефакт `oliver-200-apk`.

### Вход в аккаунт Microsoft

Нужен публичный `client_id` приложения Azure (это не секрет, но и не то,
что стоит держать в репозитории):

1. [portal.azure.com](https://portal.azure.com) → Microsoft Entra ID →
   App registrations → New registration;
2. Supported account types: **Personal Microsoft accounts**;
3. Authentication → Allow public client flows: **Yes**
   (без этого Device Code Flow не работает);
4. скопировать Application (client) ID.

Дальше — любым из способов:

```properties
# local.properties (в .gitignore)
OLIVER_MS_CLIENT_ID=00000000-0000-0000-0000-000000000000
```

```bash
export OLIVER_MS_CLIENT_ID=00000000-0000-0000-0000-000000000000
```

Для CI — секрет репозитория с тем же именем. Без него приложение
собирается и работает, но кнопка входа отключена.

### Подпись release-сборки

```properties
# local.properties
OLIVER_KEYSTORE_FILE=/абсолютный/путь/oliver.jks
OLIVER_KEYSTORE_PASSWORD=...
OLIVER_KEY_ALIAS=oliver
OLIVER_KEY_PASSWORD=...
```

Ключей в репозитории нет и быть не должно. Если переменные не заданы,
`assembleRelease` выдаёт неподписанный APK — это ожидаемо.

## Устройство проекта

```
core/   чистый Kotlin, ноль внешних зависимостей, 129 тестов
  json/     разбор JSON с лимитами глубины и размера
  hash/     SHA-1/SHA-256, сравнение за постоянное время
  io/       безопасные пути и ZIP (zip-slip, zip-бомбы)
  net/      белые списки хостов
  crypto/   контейнер секретов: два варианта
  mojang/   манифест, version.json, план загрузки, команда запуска
  auth/     офлайн-профиль: ник → UUID алгоритмом сервера
  skin/     ник → UUID → текстура, геометрия атласа скина
  shader/   распознавание паков, каталог shaderpacks/

app/    Android: экраны, сеть, Keystore, отрисовка скина
```

Такое деление не косметическое: всё, что можно сломать подменённым
манифестом или злым архивом, живёт в `core` и проверяется тестами на
обычной JVM — без эмулятора и без устройства.

## Два варианта файлов: с шифрованием и без

Каждый компонент, работающий с секретами, существует в двух подписанных
вариантах с одинаковым интерфейсом:

| С шифрованием | Без шифрования | Что общего |
|---|---|---|
| `core/crypto/CryptoEnvelope.kt`<br>AES-256-GCM, PBKDF2 210 000, AAD | `core/crypto/PlainEnvelope.kt`<br>открытый текст + SHA-256 для целостности | одинаковый API `seal`/`open` |
| `app/security/SecureVault.kt`<br>ключ в Android Keystore, envelope-шифрование | `app/security/PlainVault.kt`<br>отдельный файл настроек, только debug | общий интерфейс `Vault` |

Открытые варианты нужны для отладки: когда боевое хранилище отвечает
«контейнер повреждён», надо увидеть, что в нём лежит, не подбирая ключ
из Keystore. В release они физически не запускаются — `guardRelease()`
бросает исключение, а `VaultFactory` никогда не откатывается на открытое
хранение при ошибке Keystore.

Все файлы подписаны SHA-256 в `SIGNATURES.txt`:

```bash
tools/sign.sh --check    # проверить целостность дерева
tools/sign.sh            # пересчитать после правок
```

## Безопасность

Подробный разбор — в [SECURITY.md](SECURITY.md). Коротко: закрыты
zip-slip и zip-бомбы, path traversal через поля манифеста, SSRF через
ссылки внутри version.json, подмена артефактов (SHA-1 на каждый файл),
ReDoS через регулярки из JSON, инъекция в аргументы запуска, утечка
токена в логи и в чужое приложение, перехват трафика через
пользовательский сертификат.
